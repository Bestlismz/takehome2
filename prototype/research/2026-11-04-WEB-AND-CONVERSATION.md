# ค้นเว็บและบทสนทนาของลูกหลาน

ทบทวน 4 พฤศจิกายน 2569 ตามเวลาเอเชีย/กรุงเทพ

## หลักฐานที่ใช้

OpenAI แนะนำให้แยกบทบาท น้ำเสียง และการใช้เครื่องมือให้ชัด ใช้คำสั่งสั้น ลดคำสั่งที่ขัดกัน และปรับจังหวะด้วยคำอธิบายการพูด การเพิ่มตัวอย่างประโยคควรมีข้อกำหนดให้เปลี่ยนถ้อยคำด้วย มิฉะนั้นเสียงอาจฟังเหมือนท่องบท ตัวอย่างไม่ใช่หลักฐานว่าเสียงภาษาไทยดีขึ้นบนโทรศัพท์จริง ต้องฟังและประเมินแยกต่างหาก [Realtime prompting guide](https://developers.openai.com/cookbook/examples/realtime_prompting_guide), [Prompting Realtime models](https://developers.openai.com/api/docs/guides/voice-prompting).

Responses API มี hosted `web_search` พร้อม URL annotations และรายการแหล่งที่ค้นผ่าน `web_search_call.action.sources` การใช้ `tool_choice: required` บังคับเรียกเครื่องมือ แต่แอปยังต้องตรวจว่าการค้นและ response สำเร็จจริงก่อนแสดงคำตอบ [Web search](https://developers.openai.com/api/docs/guides/tools-web-search).

## การตัดสินใจในแอป

ใช้ backend `POST /api/web-search` เป็นขอบเขตค้นข้อมูลสาธารณะด้วย OpenAI Python SDK โดยตรง มีเพียง `query` ในคำขอ ไม่รับประวัติครอบครัว รูป เสียง หรือ records ไม่พ่วง session เดิมและไม่เก็บ response ด้วย `store:false` สามารถเรียกจาก Realtime function `web_search` ได้ ข้อมูลค้นไม่ให้สิทธิ์เรียกคำสั่งแก้แอปเอง

ทางเลือก MCP เหมาะกับคลังข้อมูลที่ทีมอนุมัติและต้องการ permission เฉพาะ จึงคงไว้ผ่าน knowledge lookup ที่มีอยู่ การค้นเว็บทั่วไปไม่จำเป็นต้องเพิ่มเซิร์ฟเวอร์ MCP อีกชั้น

ผลค้นส่ง `answer`, `sources`, `searchedAt` ให้ UI แสดงชื่อและลิงก์ ส่วนเสียงอ่านเฉพาะคำตอบสั้นกับชื่อแหล่ง ไม่อ่าน URL ยาว หาก search call ล้มเหลว response ไม่ครบ หรือไม่มีแหล่งที่ตรวจรูปแบบได้ API ไม่รายงานว่าสำเร็จ

คำค้นทั่วไปอนุญาตปี เช่น 2026 แต่ปฏิเสธรูปแบบข้อมูลติดต่อ ชื่อ และค่าตรวจที่ตรวจพบ การตรวจรูปแบบไม่ใช่ระบบตรวจข้อมูลส่วนบุคคลที่สมบูรณ์ AI ต้องย่อเป็นคำถามสาธารณะก่อนส่ง และ deployment จริงต้องมีนโยบายข้อมูลกับการประเมินการรั่วไหลเพิ่ม

คำตอบเริ่มจากเรื่องที่ผู้ใช้พูด ลดการทวน 'เข้าใจค่ะ' และการเรียกชื่อตัวเองทุกครั้ง ถามต่อเฉพาะเมื่อมีข้อมูลที่ต้องใช้จริง ยังคงอ่านทวนก่อนบันทึก แยกงานรอยืนยันออกจากงานที่ฐานข้อมูลยืนยันแล้ว บทบาทคือผู้ช่วย AI ที่ช่วยครอบครัวดูแลคนที่เรารัก ไม่อ้างว่าเป็นลูกหลานจริง

## ตรวจแล้ว

- Python tests ทั้งชุด 34 รายการผ่าน ณ การรวม backend นี้ มี 7 รายการใหม่สำหรับ web search
- การส่งผ่าน OpenAI SDK ทดสอบด้วย HTTP mock จริงของ SDK ตรวจ payload, privacy, completed search และ citations
- ทดสอบบริการจริงด้วยคำถามสาธารณะเรื่องกิจกรรมทางกายสำหรับผู้สูงอายุ ได้แหล่ง WHO ที่อ้างอิงได้หนึ่งแห่ง ไม่แนบข้อมูลผู้ใช้
- ทดสอบ syntax ด้วย py_compile และตรวจ whitespace ด้วย git diff --check

ยังไม่สรุปว่าเสียงไทยลื่นขึ้นจากการแก้ prompt จนกว่าจะฟังบทสนทนาจริง การประเมินควรครอบคลุมความเข้าใจวันที่ การพูดแทรก สำเนียง เสียงทีวี และการอ่านทวนข้อมูลในกลุ่มผู้สูงอายุ

## ข้อจำกัดก่อนบริการจริง

เซิร์ฟเวอร์นี้ยังเป็นระบบจำลองในเครื่อง ใช้ cookie แยก workspace แทนระบบสมาชิกครอบครัวที่พิสูจน์ตัวตนแล้ว ยังไม่มีการตรวจสิทธิ์ผู้ดูแลจริง โควตาค่าใช้จ่ายรายบัญชี และกระบวนการดูแล alerts โดยบุคลากร ไม่อ้างว่าการเปลี่ยน prompt หรือเพิ่มเว็บทำให้พร้อมใช้ข้อมูลคนไข้จริงทั้งหมด
